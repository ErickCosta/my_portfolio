## 1. Product vision
Build a premium, responsive, accessible, single-page personal portfolio that positions Erick Costa across three equal professional expertise pillars — Software, Data and AI — supported by a Computer Science PhD and technical leadership experience, connecting hands-on engineering with strategy and research. Site is *personal*, not Borborema Tech corporate website. Core conversion: prospective collaborators, recruiters and technical decision-makers initiate contact.

### Audiences
- International recruiters and hiring managers hiring Data Architects, Senior/Staff Data Engineers, AI Engineers and Technical Leaders.
- CTOs, engineering managers and companies seeking project-based Data & AI advisory or development.
- Research and academic collaborators.

### Goals
- Explain role and value proposition within five seconds.
- Show evidence of depth via technologies mapped to actual experiences.
- Show longitudinal career development from engineering/research to technical and executive leadership.
- Enable immediate email/LinkedIn contact and CV download (when explicitly supplied).
- Be maintainable as content-only updates, with no required backend or CMS in v1.

### Out of scope v1
Blog, authentication, user accounts, payments, AI chat, dynamic recommendations, unverified skill endorsements, self-reported percentages without a scoring model, automatic LinkedIn scraping.

### Expertise presentation methodology
- Use three to four *descriptive* labels (e.g. "Core Expertise", "Advanced Practice", "Project Experience", "Earlier Experience") and provide one or more evidence links within the site (roles/project cards).
- Alternative quantitative score only after self-assessment based on 0–4 rubric on: hands-on depth, real production use, recency, autonomy, complexity; each dimension owner-rated. Display total only if all inputs available; explain scoring and avoid equating with objective mastery.
- Include filter by category and toggle "All technologies" / "Core technologies".
- Icons are authentic SVGs from recognizable icon libraries (Simple Icons, Devicon) respecting attribution/licensing; use branded logos only where available and otherwise neutral category icon. Alt attributes required; do not depict a brand as company endorsement.
- Optional lightweight mini timeline for technology *usage*, if date evidence is sufficient, but do not imply continuous use without confirmation.

## 6. Visual system and design tokens (proposed)
- Mood: Dark Tech / Engineering Minimalism, confident and restrained.
- Colors: bg #0B1020, surface #121A2C, border #243247, text #F3F7FC, muted #9BAAC0, accent #4DA8FF, secondary accent #37D6C5. Check WCAG contrast before shipping.
- Type: strong humanist/geometric display (e.g. Space Grotesk) plus legible UI body (e.g. Inter), licensed via Google Fonts or local alternatives.
- Grid: 12-column desktop, 6 tablet, 4 mobile. Layout widths max ~1200 px; 24–32 px gutters desktop; mobile 16–20 px.
- Hero: bold left-aligned type + subtle animated architecture graph, no pseudo-code clutter; optional approved portrait.
- Components: nav, hero, metric/pillar cards, tech filter controls, skill badges, career accordion/timeline, project card, research card, contact links, footer.
- Animation: short reveal / hover microinteractions with prefers-reduced-motion support. Avoid animated numerical gauges suggesting fabricated precision.

## 8. Accessibility, responsiveness & performance acceptance
- WCAG 2.2 AA target; keyboard operable navigation and filters; semantic landmarks, meaningful focus rings, alt text, skip-to-content, no color-only encoding of skill tiers.
- Mobile widths 360/390 px; tablet 768 px; desktop 1280/1440 px. No horizontal overflow or inaccessible hover-only details.
- Largest Contentful Paint target <=2.5s, INP <=200ms, CLS <=0.1 at p75 where measurable. Lighthouse goals 90+ in Performance/Accessibility/Best Practices/SEO for production representative routes (aspirational targets, not release guarantees).
- Internal section links, contact links and language switching work; EN and PT content parity; build passes; no console errors.
- Careers can be browsed in reverse chronological order; overlapping teaching/research roles are displayed as parallel work rather than incorrectly sequentialized.

## 11. Acceptance scenarios (Given / When / Then)
- Given a new English-speaking visitor, when page loads, then English introduction, clear specialization and working contact action appear in first viewport.
- Given a mobile visitor, when navigating sections, then menu can open/close using touch and keyboard without overflow.
- Given a tech-card visitor, when choosing "Data", then only appropriately categorized cards display, with keyboard accessible filter status.
- Given a visitor asking what "Core Expertise" means, when opening help tooltip, then the non-quantitative rubric and source-based limitations are explained.
- Given a reader of career history, when expanding Techlead IT Solutions, then distinct Data Team Leader and Data & AI Manager roles display with correct dates.
- Given a visitor changing locale, when switching Portuguese/English, then visible text and metadata adapt without losing location in the page.
- Given reduced motion preference, when entering sections, then content is not dependent on motion and nonessential effects are disabled.
- Given release build, when checking project cards, then no invented clients, dates, metrics or working links exist.
